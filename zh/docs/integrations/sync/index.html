本地优先同步

通过待发送队列保存本地变更，拉取远端更新后重放待发送变更，支持离线写入与恢复投递。

@coaction/sync 是远程同步中间件，可与现有 action、选择器、observer() 和历史记录配合使用。带有变更补丁的本地提交会加入待发送队列。应用远端更新本身不会产生回传记录，空补丁提交也会跳过。

写入立即在本地生效。启用持久化时，中间件先将变更保存到待发送队列，再向服务端投递。队列写入成功后，即使进程在投递前退出，重启时仍可恢复这些变更。拉取远端更新后，中间件按冲突策略在新的远端状态上重放待发送的变更。

这不是共享权威。同步的 store 自己拥有状态并与远端 收敛；共享 store 的镜像是另一个 JavaScript 上下文中同一个权威端的视图。两者可以组合， 互不蕴含。

冲突处理函数每次接收独立的变更与补丁副本。修改这些副本不会改变待重放的队列，也不会影响下一次调用的输入。

状态必须是 JSON

待发送队列、乐观更新后的快照和适配器记录的远端状态都使用 JSON。普通 JSON 序列化会把 Date 转成字符串，把 Map 转成空对象。同步中间件在提交前拒绝引入这些值的写入，调用方会收到错误，原状态保持不变。

在写入前显式转换数据，例如将日期表示为 ISO 字符串或时间戳，将键值集合表示为普通对象，将集合表示为数组。

sync() 不能挂在外部 mutable adapter 上 —— MobX、Valtio 与 Pinia 暴露的是 accessor-backed state，这个契约在 store 构建时就会拒绝它。

默认配置需要可用的 localStorage 或自定义存储。两者均不可用时，初始化会报错。显式设置 storage: false 可使用内存队列，进程退出后尚未发送的变更会丢失。

投递语义

mutation 是至少一次投递。远端提交一次写入、到确认抵达持久存储之间的窗口无法从客户端 关闭，所以在这个窗口内崩溃意味着重启后会再发一次。请把 mutation 的 id 当作幂等键处理。
