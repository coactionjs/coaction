Coaction 4.2面向 TypeScript 的不可变响应式状态

状态随读取而动。

组件只因自己读取的路径而重渲染，getter 自动缓存，每一次写入都是可撤销、可持久化、可同步、可交给 Worker 的状态转换——用的仍是 Zustand 风格的 create()。

开始使用GitHub
$npm install coaction @coaction/react

支持ReactVueAngularSvelteSolid

核心模型

不可变状态，信号级响应，事务式更新。

Coaction 保留 React 式的不可变快照，并补上它通常缺少的两件事：读取时的细粒度依赖追踪，写入时可复用的状态转换。

不可变快照，自然的写法

在 set() 里直接写 this.user.age += 1。Mutative 把草稿变成新的冻结快照，没有改动的分支原样共享。

user└─ profile├─ name<UserName />└─ age无人读取

普通对象，信号级精度

读取会在 alien-signals 上构建路径依赖图。读取 user.profile.name 的组件不会因 age 的变化而更新，模型里也不需要 Signal<T> 或 Atom<T>。

会自己缓存的 getter

普通的 get total() 就是带缓存的计算值。依赖自动发现，所有读取者共享同一个结果。

每次写入都是一次状态转换

set() 产出下一份快照和一次提交，按需附带补丁。撤销重做、持久化、同步和 Worker 都建立在它之上。

实时演示

点一个 action，数一数重渲染。

这里运行的就是本仓库里的 Coaction。每个单元格都是一个会统计自身渲染次数的组件：左列用 observer() 包裹，右列是订阅整个 store 的普通 useShop()。

import { create } from '@coaction/react';

export const useShop = create((set) => ({
  user: { name: 'Ada', age: 36 },
  cart: { items: [{ name: 'Notebook', price: 12 }] },
  theme: 'light',

  get total() {
    return this.cart.items.reduce((sum, item) => sum + item.price, 0);
  },

  rename(name: string) {
    set(() => {
      this.user.name = name;
    });
  },
  birthday() {
    set(() => {
      this.user.age += 1;
    });
  },
  addItem(item: Item) {
    set(() => {
      this.cart.items.push(item);
    });
  },
  setTheme(theme: 'light' | 'dark') {
    set(() => {
      this.theme = theme;
    });
  }
}));

更少的胶水代码

同一个计数器，省掉选择器的管道。

Coaction 的 store 读起来就像 Zustand 的 store。消失的是那些只为避免多余渲染而写的代码：选择器、浅比较和手写的记忆化。

  • 组件里没有选择器
  • doubled 不需要依赖数组
  • 不用手写记忆化

需要时，选择器、createSelector() 与 useStore(selector) 依然可用。 从 Zustand 迁移

状态转换

每一次写入，都是可复用的状态转换。

set() 把一段修改配方变成下一份快照和一次提交。功能需要时，提交会携带补丁与逆向补丁；撤销重做、持久化、同步和共享运行时都建立在它之上，不必各自发明写入语义。

set(() => { this.todos.push(todo) })
提交补丁 + 逆向补丁
  • 响应式追踪coaction

    只让读取了变化部分的消费者失效。

  • 撤销 / 重做@coaction/history

    用逆向补丁前进与后退。

  • 持久化@coaction/persist

    保存提交；迟到的恢复不会覆盖新的编辑。

  • 本地优先同步@coaction/sync

    持久化发件箱，在拉取的远端变更之上变基。

  • 协同编辑@coaction/yjs

    把 store 绑定到 Yjs 文档。

  • 共享运行时coaction/shared

    Worker 中唯一的权威，每个标签页一份镜像。

适用场景

Coaction、Zustand 还是 MobX？

getter、this 和自动追踪并不新鲜，MobX 已经提供了十年。少见的是把它们放在不可变的底座上、藏在 Zustand 风格的 create() 后面，并且横跨五个框架。

坦白说

大多数应用并不需要它。

如果只是单个标签页里的少量状态，Zustand 或 Jotai 依赖更小、生态更大。当你同时需要下面其中几项时，Coaction 才值得引入：

  • 带自动深度渲染追踪的不可变快照
  • 无需手写记忆化的缓存派生状态
  • 写法像可变、结果却不可变的更新
  • 建立在同一套状态转换上的撤销、持久化或同步
  • 以 Worker 或 SharedWorker 作为同一份状态的权威
  • 本地优先的远程同步
  • 一套能持续生长、无需第二个运行时的模型

先了解代价：在依赖外置的情况下，coaction 使用方测试包约 10.7 KiB（gzip）；在“每次更新后都读取”的场景中，吞吐量约为 Zustand 的一半。
