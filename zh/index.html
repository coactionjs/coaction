Coaction 4.2面向 TypeScript 的不可变响应式状态

按读取路径追踪状态依赖

React 组件在 observer() 内追踪渲染时读取的状态路径，普通 useStore() 则订阅整个 store。getter 的计算结果由运行时缓存。使用 Zustand 风格的 create() 创建不可变 store。撤销、持久化和远程同步可通过中间件启用，共享模式还支持在 Worker 中执行 action。

核心模型

不可变快照、路径依赖追踪与事务式更新

组件读取状态时，Coaction 记录它依赖的路径。更新提交后，运行时根据新旧快照判断哪些依赖发生了变化。

在草稿中修改状态

在 set() 的更新函数中执行 this.user.age += 1，提交后会得到新的不可变快照。未修改的分支仍与上一个快照共享同一引用。

user└─ profile├─ name<UserName />└─ age无人读取

按属性路径追踪读取

在 observer() 中读取 user.profile.name 时，Coaction 会记录这条路径。仅修改 user.age 不会因此触发该组件重新渲染。对象属性无需单独声明为信号。

getter 的依赖与缓存

运行时记录 get total() 读取的状态字段，并缓存结果。多个调用方可复用该结果，依赖变化后再次读取时才重新计算。

每次写入都是一次状态转换

set() 产出下一份快照和一次提交，按需附带补丁。撤销重做、持久化、同步和 Worker 都建立在它之上。

实时演示

两种订阅方式下的组件渲染次数

执行下方的 action，可对比同一次更新触发的渲染次数。左列组件通过 observer() 追踪读取路径，右列组件通过 useShop() 订阅整个 store。每个单元格分别计数。

import { create } from '@coaction/react';

export const useShop = create((set) => ({
  user: { name: 'Ada', age: 36 },
  cart: { items: [{ name: 'Notebook', price: 12 }] },
  theme: 'light',

  get total() {
    return this.cart.items.reduce((sum, item) => sum + item.price, 0);
  },

  rename(name: string) {
    set(() => {
      this.user.name = name;
    });
  },
  birthday() {
    set(() => {
      this.user.age += 1;
    });
  },
  addItem(item: Item) {
    set(() => {
      this.cart.items.push(item);
    });
  },
  setTheme(theme: 'light' | 'dark') {
    set(() => {
      this.theme = theme;
    });
  }
}));

同一个计数器，两种订阅写法

Coaction 示例用 observer() 追踪组件读取的字段，用 getter 缓存 doubled。组件无需手动组合选择器，也无需调用 useShallow 或 useMemo。

  • 自动收集 doubled 的依赖

状态转换

从状态更新到提交与补丁

set() 的更新函数在草稿上修改数据。运行时提交新状态，并可按需生成正向和逆向补丁，供历史记录、同步等集成使用。

set(() => { this.todos.push(todo) })
提交补丁 + 逆向补丁
  • 响应式追踪coaction

    只让读取了变化部分的消费者失效。

  • 撤销 / 重做@coaction/history

    撤销时应用逆向补丁，重做时应用正向补丁。需要保留对象引用关系时可使用快照。

  • 持久化@coaction/persist

    保存选定的状态。恢复时按 merge 策略合并，默认由存储值覆盖同名字段。

  • 本地优先同步@coaction/sync

    默认持久化待发送的本地变更。拉取远端更新后，按冲突策略在新基线上重放这些变更。

  • 协同编辑@coaction/yjs

    把 store 绑定到 Yjs 文档。

  • 共享运行时coaction/shared

    Worker 持有可写状态，每个连接的页面维护自己的镜像。

Worker 持有状态，页面代理 action 并镜像每次提交。

Worker
// worker.ts
import { create } from '@coaction/react/shared';
import { counter } from './counter';

create(counter);

// App.tsx
import { create } from '@coaction/react/shared';
import { counter } from './counter';

const worker = new Worker(new URL('./worker.ts', import.meta.url), {
  type: 'module'
});
const useCounter = create(counter, { worker });

适用场景

Coaction、Zustand 还是 MobX？

Coaction 提供 Zustand 风格的 create() 接口，在不可变快照上支持 getter、绑定到状态的 this 和读取依赖追踪。下表对比三种库的状态模型与订阅方式。

选型依据

应用需要哪些状态管理能力？

单标签页内只有少量状态时，可先评估组件本地状态。需要跨组件复用派生结果、追踪嵌套字段或跨线程共享状态时，可按下列能力比较方案。

  • 带自动深度渲染追踪的不可变快照
  • 无需手写记忆化的缓存派生状态
  • 写法像可变、结果却不可变的更新
  • 建立在同一套状态转换上的撤销、持久化或同步
  • 以 Worker 或 SharedWorker 作为同一份状态的权威
  • 本地优先的远程同步
  • 本地模式与共享模式可复用符合共享约束的状态定义

依赖外置时，coaction 使用方测试包经 gzip 压缩约为 10.7 KiB。在 4.0 的购物车基准中，每次更新 1,000 项中的一项后读取总价，Coaction 缓存 getter 为 48,480 次/秒，Zustand 选择器重算为 88,113 次/秒。
